## 1. Java Script memory allocation, impace on performance and memory saftey

### Varibale memory allocation
> When creating objects, array, and functions in Java Script they are allocated in the heap. Meaning that the this is dynamic allocation so the size of the data structers can change at runtime. Local variables and funcations call information is stored on the stack

### Memory Managment
> Java Script's V8 engine uses a garbage collector to automatically identify and reclaim memory that is no longer needed. The gargbage collector in Java Script uses the Mark and Sweep algorithm where the garbage collector periodically scans the memory and marks objects that are still reachable and sweeps away the objects that are no longer reachable. 

### Impact on performance and memory saftey
> Memory leaks are resolved because of the automatic garbage collection since there is no manual memory managment. There is still a risk though of memory leak if refrences to unused objects are intentionally retained. There are however no issues with dangling pointers since pointers are not implemented in the language. The grabage collector does introduce some overhead cost when it comes to performace since its periodic scanning causes pauses in order to reclaim memory.

## 2. Types system and type checking
 
>Java Script is dynamically typed so types are determined at runtime rather than at compile time. Java Script variables can hold any type, and their types can change during execution time. Meaning that variables can be assignmed to type string and then later be reassigned to a number. Javascript also does not require explicit type declaritions leading to more flexibility during the development life cycle. Type errors in Java Script are only detecable during run time making errors like this harder to debug

## 3. Subprogram calling conventions
> In Java Script functions are first class objects which means that functions can be assigned to variables, passed as arguments to other functions, returned from functions, or they can be stored in data structers. When a function is called a new exectuion context is created and pushed onto the call stack. The exectuion context that is created includes a varibale enviornment, a lexical enviornment, and also what is know as this binding. The variable enviorment can be seen as a table that holds function arguments, local variables, and function declarations inside the function. The lexical enviornment contains a refrence to the scope in which the function was defined, allowing the fucntion to acces variables from its parent scope this behaviour in Java Script is called lexical scoping or static scoping. the this binding refers to the context object that a function is operating on. Its value depends on how the function is invoked: in regular functions, this refers to the global object or is undefined in strict mode; in object methods, it refers to the object; and in arrow functions, it lexically inherits this from the surrounding scope. After the function finishes executing, its context is removed from the call stack. These mechanisms together ensure JavaScript can manage scope, memory, and function behavior effectively during runtime.

## 4. Variable scope and lifetime

>Java Script variables are accessible by where they were declared in the source code. There are three main types of scopes: global, function(local), block. Variables declared outside of any function or block are considered global variables and there lifetime is throughout the duration of the program. variables declared with the keyword const and let are block scoped meanning that they are only accessible within the block they were defined in. The lifetime of a variable begins when its containing scope is enterd and ends when that scope is exiited.

## 5. Unique feature of the language 

> A unique feature of Java Script is first-class functions and closures, which allow functions to be treated as values. This means functions can be assigned to variables, passed as arguments, returned from other functions, and even nested inside other functions. Closures make it possible for inner functions to retain access to variables from their outer scope even after that scope has exited. This allows developers to emulate private state, build factories, and manage asynchronous behavior elegantly. While powerful, this feature comes with trade-offs: it can lead to memory leaks if closures unintentionally hold references to large objects, and it can make debugging more complex due to retained execution contexts.
